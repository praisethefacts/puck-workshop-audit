Verdict: BENIGN / WITH CAVEATS Risk score: 26/100 (Moderate) Kind: managed .NET mod (Stats fork + installed-mod inventory reporter) Author: 76561198936609274 · Published/updated: 2026-08-16 11:28 UTC · Subscribers: 737 · On-disk size: 0.10 MB

What it is #

A fork of the "Stats" mod (same namespace, same assembly name oomtm450PuckMod_Stats, same stats patches) with an added "GPM" subsystem that inspects which mods a connecting client has loaded and reports that list to the game server. The server stores the per-player mod inventory in a JSON file. It is a server-owner moderation/visibility tool; it does not contact any internet host.

Contents #

  • 1 file / 106,496 bytes: only oomtm450PuckMod_Stats.dll — note the same filename as the official Stats mod (3561076649), so the two cannot coexist and this fork also overwrites/conflicts by assembly identity.
  • oomtm450PuckMod_Stats.dll — 106,496 B, managed .NET (dotnet=1), PE32 machine=i386, signed=0, sections .text/.rsrc/.reloc, overlay 0, entropy 5.83 (normal IL).
  • All hashes are in evidence/hashes_sha256.txt; PE facts in evidence/pe_info.txt; decompiled source in sources/.

Code analysis #

  • 34 decompiled files. Two subsystems:
    1. Stats (inherited from upstream): Harmony patches at Stats.cs:24,48,217,242,333,362,555,614,643,851,935,990,1071,1104,1193,1211,1231 (spawn, score, scoreboard, voting, physics, collisions, chat prefix, ticking) with Netcode counters via NetworkCommunication.cs:34,59.
    2. GPMMods (the fork's addition): ModScan, ModsNet, ModsSrv, ModsLog, ModsConst and patch Gpm_ModScan_Update_Patch.
  • Mod enumeration — sources/oomtm450PuckMod_Stats/GPMMods/ModScan.cs:
    • ScanModManager (ModScan.cs:59-76) resolves the game's ModManager type via AccessTools.TypeByName, instantiates it (InstanceOf), walks all public/non-public properties and fields and feeds any enumerable whose elements' type name contains "Mod" into TryCollection (:78-103), which extracts each mod's Id/IsEnabled and classifies numeric IDs as workshop IDs (:96-99).
    • ScanChainloader (:105-123) additionally enumerates BepInEx Chainloader.PluginInfos and takes plugin Metadata.GUID/Name.
    • Payload built as tab-separated id / enabled / local / workshop / source (ModScan.cs:40-57, Merge at :125).
    • This is read-only reflection over already-loaded mods — no assembly loading of new code, no file scanning of arbitrary directories.
  • Transmission — Gpm_ModScan_Update_Patch.cs (Harmony postfix on PhysicsManager.Update, :8): on a server it registers the named-message handler "GPMStat_client" (:52); on a client, 3 seconds after connecting (:72) it builds the payload and sends it to the server via ModsNet.SendToServer("mods", payload) (:75-76).
  • Storage (server side) — ModsSrv.cs:126-157: writes gpm_client_mods.json into the server's current working directory, atomically via .tmp + move (:144-151), containing written_at and a players map keyed by the player (SteamID) with each mod's id, workshop_id, name, file, local, enabled, source (:100-119).
  • Also inherited: live stats file oomtm450_stats_live.json (Stats.cs:1589), Stats config JSONs, NetworkCommunication Netcode messaging.
  • Absent: no HTTP/WebClient/Socket of any kind — the only transport is Unity Netcode inside the game session (0 risky-API hits across 34 source files); no registry, no Process.Start, no DllImport, no crypto, no base64, no clipboard/keylogging, no Steam auth-ticket/credential access, no persistence, no downloads or execution of fetched code.

Findings #

  1. Client uploads its complete installed-mod inventory to whatever server it joins — ModScan.cs:16-57 (build payload), Gpm_ModScan_Update_Patch.cs:75-76 (send after connect), ModsNet wrapper. Sent content is mod IDs/workshop IDs/names plus enabled/local flags. Severity: medium (privacy). It is not credentials or files, but it lets any server operator fingerprint a client's mod set, including private/local (non-workshop) mods.
  2. Server writes a persistent per-player profile to disk — ModsSrv.cs:126-157, file gpm_client_mods.json in the server CWD, keyed by player identity, including local (non-workshop) mod names. Severity: medium (retention of user-mod data on third-party servers).
  3. Reflection-based mod enumeration — ModScan.cs:59-123 walks ModManager and BepInEx Chainloader internals. Read-only, but coupled to game internals and can silently break on updates; no code is loaded or executed from the scan. Severity: low.
  4. Assembly/DLL name collision with upstream Stats — evidence/FACTS.md (same oomtm450PuckMod_Stats.dll, same namespaces/types). Installing both will produce duplicate-type/load conflicts; only one should be used. Severity: low (stability, not security).
  5. Fork is otherwise identical in behaviour to upstream Stats — same patches and Netcode stats counters; no additional network or filesystem capability beyond the mod-list reporter. Severity: informational.
  6. Suspicious-looking metadata date — workshop "published" is 2026-08-16, later than the current analysis date; treat the timestamp as unreliable metadata rather than a behavioural signal. Severity: informational.

Bottom line #

Keep only if you accept the caveat: when you join a server, this mod tells that server the list of mods you have installed (including local ones), and the server saves it to a file; it does not talk to the internet or touch anything else.
