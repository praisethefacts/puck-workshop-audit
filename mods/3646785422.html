What it is #

A large practice/training mod for Puck. It adds a practice mode with AI goalies and skaters, spawnable props and cloned rink sheets, stamina and warm-up tweaks, a mod menu hub, config sync between host and clients, and detectors for other installed mods so they cooperate.

It is one of the heaviest-patching mods in this set: 84 source files, 114 types, and Harmony patches against 17 distinct game types. The DLL is the whole mod — no assets, no native code.

Code analysis #

Bootstrap. MaxPracticePlugin.cs implements IPuckPlugin; OnEnable() builds a Harmony, then patches both by attribute (PatchAll) and dynamically via AccessTools.DeclaredMethod for methods whose names differ between game builds — e.g. MaxPracticePlugin.cs:222–:225 resolves "FixedUpdate" and attaches PracticeStaminaPatch.Postfix, :231–:234 tries "Server_Tick" then "Server_OnGameStateTick" and attaches WarmupTimerPausePatch.Prefix. That reflection fallback is version compatibility, not evasion.

Harmony patches — 81, across 17 game types: ChatManager, ConnectionApprovalManager, Movement, Player, PlayerBody, PlayerLegPad, PlayerManager, Puck, PuckElevationIndicator, ReplayRecorder, Stick, StickPositioner, TCPServer, UIChat, UIMinimap, UIScoreboard, VoteManager. Representative attributes: FakeClientNetworkManagerCleanupPatch.cs:5 [HarmonyPatch(typeof(Player), "OnNetworkDespawn")], FakePlayerStickCollisionPatch.cs:7 [HarmonyPatch(typeof(Stick), "OnNetworkPostSpawn")], FakePlayerStickFixedUpdatePatch.cs:5 [HarmonyPatch(typeof(Stick), "FixedUpdate")], PracticeCommandPatch.cs:9 [HarmonyPatch(typeof(ChatManager), "Client_SendChatMessageRpc")], VoteManager_Server_AddVote_Patch.cs:8 [HarmonyPatch(typeof(VoteManager), "Server_AddVote")]. This is a broad rewrite of game behaviour — normal for a practice-mode mod, but it means the mod can break, or subtly change game outcomes, after any game update.

The fake-player (AI goalie) subsystem is deliberately hidden. MaxPractice\MaxPractice\GoalieAIManager.cs spawns synthetic players with fixed client IDs RedClientId = 1111112UL / BlueClientId = 1111111UL (:268–:270), filtered by FakePlayerDetector.IsAnyFakeClientId(...). To keep them out of normal UI and stats the mod patches:

  • PlayerManager.GetPlayers / GetSpawnedPlayers postfixes that strip fake players from the returned list (:35–:59);
  • Puck.GetPlayerCollisions / GetPlayerCollisionsByTeam postfixes that strip fake-player touches (:240–:264);
  • ChatManager.Server_BroadcastChatMessage prefix that suppresses the "DummyRed/DummyBlue has joined/left the server" lines (:13–:33);
  • TCPServer.SendMessageAsync prefix that rewrites the game's own outbound JSON so "players" is decremented by the number of fake clients (:61–:94, TCPServerPreviewResponse deserialise at :88, re-serialise at :92);
  • ConnectionApprovalManager.GetConnectionRejectionCode postfix that cancels a "server full" rejection when the slots are only taken by fake clients (:214–:238).

The intent is benign (practice bots should not count against the player cap and should not spam chat), but the effect is that a server running the mod reports a player count and roster that excludes the bots. TCPServerPreviewResponse is a Puck game type for the game's own TCP server-preview channel — the mod is editing a message the game itself sends; it does not create a network client.

Network — no client networking of its own beyond netcode, no internet transport. There is no HttpClient, WebClient, WebRequest, Socket, TcpClient, UdpClient or Steam API call in any of the 84 files; evidence/api_surface.txt has no [Network] section. The mod's own traffic uses Unity Netcode named messages registered on "MaxPractice/ClientVersion" (ClientVersionCheck.cs:65), "MaxPractice.Props" (PropNetwork.cs:96), "MaxPractice.RinkChunks" (RinkChunkSync.cs:376), "MaxPractice.Sheets" (RinkSheetNetwork.cs:66), "MaxPractice.YoyoString" (YoyoStringNetwork.cs:86) — all carrying gameplay sync (props, rink chunks, sheet layouts, custom string physics) inside the existing lobby session. No URL, host or port is hard-coded anywhere in the mod.

Findings #

  1. 81 Harmony patches across 17 game types, including GameManager-adjacent state, VoteManager.Server_AddVote, UIScoreboard, Puck collision queries and ConnectionApprovalManager. This is the largest behavioural footprint in the set. No malicious effect, but the mod can change vote outcomes, puck-touch attribution and who is allowed to connect, and it will break on game updates. Severity: moderate (the caveat in the verdict).
  2. Synthetic players are hidden from the game's own roster and player-count reporting. GoalieAIManager.cs:35–:59 (strip from GetPlayers/GetSpawnedPlayers), :13–:33 (suppress join/leave chat), :61–:94 (rewrite TCPServer JSON to decrement players), :214–:238 (cancel "server full"). Legitimate for practice bots, but on a shared server the operator's own tooling under-reports occupancy. Severity: moderate.
  3. ConnectionApprovalManager.GetConnectionRejectionCode patch can admit a client the game wanted to reject (GoalieAIManager.cs:222–:232: if the rejection code is 1 and the non-fake client count is below maxPlayers, __result = null). Narrowly scoped to the "server full" case and only corrects for bots, but it is a change to the admission path. Severity: moderate.
  4. Discovers and drives other installed mods' menu objects via non-public reflection (CompTweaksDetector.cs:25, ModMenuHub.cs:95, PonceMods.Shared\ModMenuHub.cs:103–:104). Read-only access to a known, same-family type; no loading of foreign code. Severity: low.
  5. Writes a local mod-menu registry and its own config JSONs (ModMenuHub.cs:79–:91, :152; ConfigManager.cs:76/:82; MaxPracticeKeybindManager.cs:155). No deletions, no user data. Severity: informational.
  6. Automated scan artefacts: the two [Crypto]-looking categories are false. evidence/hits_summary.txt records magic-signature hits: 0 ; keyword hits: 0, the only binary hit is MaxPractice.dll 0 MZ (the DLL's own header), and the 19 [Crypto] lines are the substring "aes" inside identifiers like handlersAttachedSoFar. Severity: informational.

Bottom line #

Keep, with a caveat. Nothing in it talks to the internet, touches the registry, or persists anything — it is a very invasive gameplay mod, not malware. The caveat is the fake-player subsystem: it hides its practice bots from player lists, chat and the server's own player-count reporting, and it can override the game's "server is full" rejection. That is defensible for a practice bot and is not hidden maliciously, but if you run a public server you should know your roster and slot counts will under-report while it is loaded.
