What it is #

A small ice-hockey training/practice mod: it loads a custom AssetBundle of training prefabs (goal tarps, wall targets, circular targets, a half-rink hockey setup, puck passers) and lets the server spawn them with chat commands (/goaltarps, /cleargoaltarps, /targetpractise, /cleartargetpractise, /passer), plus local puck-drill hotkeys (middle mouse to place the puck, V to pass, B for an incoming-puck drill, X for a lob pass). The DLL is required. It is a hobby-quality Debug build (assembly still named MyMod, AssemblyConfiguration("Debug")), but its behaviour is entirely in-game.

Code analysis #

Bootstrap. MyMod.Class1 : IPuckPlugin (Class1.cs:10). OnEnable resolves its own directory, then loads every file in it that is named trainingprefabs* or has .bundle/.assetbundle/.unity3d (:29-46), calls AssetBundle.LoadFromFile on each (:56), registers the four known prefab names <TrainingPrefab, Goaltarp, WallTarget, halfrinkhockey> (:18) plus every GameObject asset in the bundle (:82-133), and creates a DontDestroyOnLoad("FlamiePrac_Manager") with TrainingObjectManager + PuckSpawner (:139-142). OnDisable unloads cleanly (:153-171). No Harmony at all — the mod subscribes to the game's public events instead.

Game integration. TrainingObjectManager.Start registers a listener for Event_Server_OnChatCommand (TrainingObjectManager.cs:64); the handler requires NetworkManager.Singleton.IsServer (:90) and dispatches the five chat commands (:106-123), spawning Object.Instantiate clones of the registered prefabs named Training_<prefab>_<n>, capped at 50 objects (:31, :315), tracked per player (playerObjects). Chat replies go through ChatManager.Server_BroadcastChatMessage (:852-869). Local drills are in PuckSpawner.Update: reads Unity Input System keys — middle mouse, V, B, X (PuckSpawner.cs:36-52) — and teleports the local puck / spawns a drill. This is ordinary game input reading through Unity's input API, not a keyboard hook.

Network: none of its own. No HttpClient, WebClient, WebRequest, Socket, TcpClient, UdpClient, Dns, no UnityWebRequest at all (verified by source-wide grep; evidence/api_surface.txt has no [Network] section for this DLL). Everything happens over the game's existing Netcode connection. No Steamworks API, no GetAuthTicket, no credentials/tokens/cookies.

Filesystem. Only reads: enumerates its own mod directory and loads the bundle files (Class1.cs:29-56). Nothing is written, deleted, or created on disk. No registry access, no Process/ProcessStartInfo (the single [Process] hit is an unused using System.Diagnostics; in Properties/AssemblyInfo.cs:1), no DllImport/Marshal, no Assembly.Load, no injection or thread manipulation, no persistence, no crypto or obfuscation (the 3 [Crypto] hits are Shader.Find("Universal Render Pipeline/Lit") substring false positives), no clipboard/screen capture, no environment variable access.

Findings #

  1. Only network surface is the game's own Netcode + chat event. NetworkManager.Singleton.IsServer gate (TrainingObjectManager.cs:90); no sockets or HTTP. Severity: informational.
  2. Chat commands are not admin-gated. Any client whose / command reaches Event_Server_OnChatCommand can spawn/clear training props on the server (:106-123), capped at 50 objects and tracked per SteamID/owning client. Social/abuse surface at most, not a security issue: it cannot touch files, network, or other processes. Severity: low.
  3. Dead "safe mode"/teleport helpers exist but are never called. DisableEverythingExceptPlayers (:153-174) and HandleTeleportCommand (:259-281) are defined but not wired to any command or event — worth noting only because they read dangerously by name (they would disable scene renderers/colliders locally). Severity: informational.
  4. Local input reads are Unity Input System scancodes (middle mouse / V / B / X) for puck drills (PuckSpawner.cs:36-52). No GetAsyncKeyState, no global hook, no logging of keystrokes. Severity: informational.
  5. Bundle discovery accepts arbitrary .bundle/.assetbundle/.unity3d files placed next to the DLL (Class1.cs:42). That is a local-folder trust issue only — whoever can already write into the mod folder owns the game install; the loaded content is Unity assets, never code. Severity: informational.
  6. Absent categories (checked in sources + evidence/api_surface.txt): no network APIs of any kind, no Steamworks auth, no credential/token/cookie/clipboard/screen access, no registry, no process creation, no P/Invoke, no Assembly.Load, no persistence, no crypto, no downloads.
