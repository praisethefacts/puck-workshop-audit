What it is #

"Rink" (build B330) is a large total-conversion / league-rules mod for Puck: ~99 Harmony patches over movement, puck feel, tackling, goalies, sticks, benches/substitutions, match intro & goal presentation, scoreboard and UI, plus custom 3D models (gloves, bench, LED boards, broken sticks) and a "Rink PUG" ruleset served from the author's site. It also embeds a substantial analytics/league plumbing layer: on any server running it, the mod uploads SteamIDs, player names, playtime and stored per-player settings to https://rinkpuck.com/api/stats, pulls stick-skin assignments and images from the same host, shows a league scoreboard/news tab, and can auto-update itself through Steam Workshop. No credential, token, process, registry or persistence abuse exists in the code; the risk is consent and data breadth, not capability.

Code analysis #

Bootstrap and patching. Rink.Plugin : IPuckPlugin (Plugin.cs:9). The Harmony id is namespace-switched between hand-installed and Workshop copies (com.puckcreatorrink.Rink / …Rink.workshop, Plugin.cs:27-35). A static ctor registers an AssemblyResolve hook that Assembly.LoadFiles deps\RinkApi.dll (Plugin.cs:36-47). OnEnable refuses to run if another install already set Rink.Plugin.Running (reflection scan of loaded assemblies, :52-58,92-131), creates DontDestroyOnLoad("Rink Plugin") with RinkBehaviour, attaches the four network reporters (:64-67), applies every [HarmonyPatch] class via CreateClassProcessor (:134-168), and calls RinkApi.Register("Rink","B330"). OnDisable unpatches and unregisters (:170-200).

Patched game methods (41 distinct targets, ~99 attribute uses). Movement/feel: PlayerInput.UpdateInputs/ClientTick/UpdateLookAngle/Server_BladeAngleInputRpc/Server_RaycastOriginAngleInputRpc, PlayerBody.FixedUpdate/HandleInputs/OnNetworkPostSpawn/OnCollisionEnter/Server_OnCollisionDeferred/DashLeft/DashRight/extended-state setters, PlayerLegPad.Awake/Update, VelocityLean.Awake, Movement.FixedUpdate, Puck.OnCollisionEnter, Stick.OnCollisionStay, GameManager.Server_StartSlowMotion. Presentation/UI: UIView.Show/Hide, UIAppearance.Initialize, UIScoreboard.Initialize/StylePlayer, UIPositionSelect.Update, PlayerHead.SetHeadgearID, StickMesh.SetSkinID, LockerRoomStick.SetSkinID, LockerRoomPlayer.SetLegsPadsActive. Chat: ChatManager.Client_SendChatMessageRpc and ChatManager.Server_SendChatMessage(string,string,ulong[]) (in-game command/menu plumbing). All of these are ordinary gameplay/logic patches; none hook crypto, auth, Steam ticket APIs or process APIs.

Network — all hosts are the author's. Every request in the mod is HTTPS to rinkpuck.com, plus one Cloudflare Worker used for match presets:

  • RinkApi (deps\RinkApi.dll, RinkApi.cs:69-157): "mod_heartbeat" every ~60 s — {api:1, kind:client|server, sid:<SteamID64>, name:<player name>, server:<MachineName|server name>, mods:{…}, time} POSTed to …/api/stats with hardcoded header x-rink-key: iZIcx2y-h29cC2GNes4SI03qtNSrK8vh (:29-31,144-151). Response ignored.
  • NameReporter (NameReporter.cs:41,137-160): server-only, every 60 s, POST action:"player_join" with each connected player's steamId + name not yet sent (:96-133 filter: SteamID length ≥ 15, name ≤ 64 chars).
  • PlaytimeReporter (PlaytimeReporter.cs:79,101): server-only, every 60 s, POST action:"playtime_report" with {steamId, seconds:60} per player.
  • SettingsReporter (SettingsReporter.cs:50,96-137): server-only, every 120 s, reads config\rink_players\*.json (:87-100) and POSTs action:"player_settings_report" with {steamId, updatedAt, Rink:<settings>, Puck:<settings>} — i.e. the server's stored per-player feel/settings snapshots are uploaded to the author's backend.
  • ApiStats (ApiStats.cs:54-95,112-135): off unless the server operator puts an ApiUrl (and optional ApiKey) in rink.json; then it POSTs {ApiUrl}/api/match with mode/level/score and per-player goals/assists/shots/saves/goalsAgainst plus SteamIDs. Used by league sites to ingest match stats.
  • StickSkinSync (StickSkinSync.cs:81,96-140): every 30 s GET …/api/stats?mode=stick_skins (with the API-key header) → assign map SteamID→skin id and a catalog of roles.
  • CustomStickSkin (CustomStickSkin.cs:26,66-133): GET …/api/stats?mode=stickimg&id=<skinId> → JSON {ok, data:"data:image/…;base64,…"} → Convert.FromBase64String → ImageConversion.LoadImage(texture) → assigned to the stick material. Image data only; nothing is written to disk or loaded as code.
  • ScoreboardTab (ScoreboardTab.cs:93-95,590-650): GET …/api/stats?mode=data and renders teams/standings/matches/news in a UI tab; JoinPanel opens https://rinkpuck.com/ via SteamFriends.ActivateGameOverlayToWebPage or Application.OpenURL (JoinPanel.cs:11,125,129).
  • RinkBehaviour (RinkBehaviour.cs:50,268-295): when hosting and the server name starts with RINK | PUG # or RINK SCRIM #, GET https://rinkbot.erscup910.workers.dev/preset/rink.json, deserialise into RinkConfig and apply. That is a static JSON tuning preset (all fields are gameplay floats/bools, RinkConfig.cs), not executables or URLs.

Server scoping. Dedicated servers are restricted to one community IP: IsAllowedServer returns true only for 37.114.57.48 (the CommunityServerIp constant) or for non-IP/local endpoints (RinkBehaviour.cs:49,113-135,600-637). So the analytics uploads are gated to servers the author controls/operates, not arbitrary community servers.

In-game networking. NetworkSync defines a private named-message protocol ("Rink_server" / "Rink_client") with 30 message types (stick break, bench, substitutions, glove holds/throws, board impact, admin request/roster/action, config chunks, client prefs) and 900-byte chunking for RinkConfig JSON and player prefs (NetworkSync.cs:9-90). It runs over the game's existing Unity Netcode connection — no sockets of its own.

Local files. Everything written stays under the game's config folder (RinkBehaviour.ConfigFolder = <game dir>\config, RinkBehaviour.cs:76-80): rink.json (tuning + optional ApiUrl/ApiKey), presets.json (Presets.cs:45-47), rink_players\<steamid>.json per-player settings snapshots (PlayerPrefsStore.cs:88-116, including deletion of its own stale records), and rink_client.json with a one-time cloud_client.json migration (ClientPrefs.cs:27-38). AutoUpdate locates its own Workshop item id, and if Steam reports it missing/outdated calls SteamWorkshopManager.SubscribeItem/DownloadItem, logging that the new build loads next launch (AutoUpdate.cs:33-90) — updates come through Steam, never from a URL.

Absent. No registry access, no process creation/shell, no DllImport/Marshal, no injection, no persistence (no Run key, task, service), no crypto/obfuscation of user data, no credential/Steam-ticket/cookie/clipboard/keyboard/screen access, no hidden downloads: every HTTP GET is consumed as JSON for UI/tuning or as a texture. Assembly.LoadFile appears once and only for the shipped deps\RinkApi.dll.

Findings #

  1. Broad, always-on telemetry to rinkpuck.com with a hardcoded API key, and no opt-out. Client: SteamID64 + display name + installed-mod versions every ~60 s. Server: per-player SteamID/name joins, playtime ticks, and uploaded copies of stored per-player settings; optional per-match stats only if the operator configures ApiUrl. This is disproportionate for a gameplay mod and is the reason for the caveat, but it is plain HTTPS JSON to one host, the response is never acted upon, and no secrets (tickets, tokens, cookies, IPs, files) are collected. Severity: moderate (privacy/consent).
  2. Two author-controlled hosts plus one Cloudflare Worker. rinkpuck.com (stats/skins/scoreboard/join link) and rinkbot.erscup910.workers.dev/preset/rink.json (match-preset JSON, only when hosting a RINK | PUG #/RINK SCRIM # server). Both are behaviourally limited to JSON/texture data; the workers.dev endpoint applies a fixed RinkConfig schema with no URLs or code fields. Severity: low.
  3. Remote images decoded in-process. Convert.FromBase64String → ImageConversion.LoadImage → Texture2D (CustomStickSkin.cs:73-120). Parses attacker-supplied PNG bytes at worst; no file write, no code path. Severity: low.
  4. Self-update via Steam Workshop only (AutoUpdate.cs:33-90): subscribes/downloads its own item through the game's Steam integration. No external binary fetch, no silent execution. Severity: informational.
  5. Heavy game-internal reflection (~37 sites) and ~99 Harmony patches, including server-side enforcement of movement/stick values. These are anti-cheat/consistency features of a competitive-rules mod, not obfuscation or injection; patches are cleanly applied in OnEnable and removed in OnDisable. Severity: informational.
  6. Local config writes stay in <game>\config (RinkBehaviour.cs:76-80, Presets.cs:47, PlayerPrefsStore.cs:109); Application.OpenURL/Steam overlay is user-initiated from the join panel. Severity: informational.
  7. Absent categories (checked against evidence/api_surface.txt + all 136 source files): no registry, no process/shell, no P/Invoke/Marshal, no remote code load, no persistence, no user-file crypto, no credential or Steam-auth-ticket access, no input/clipboard/screen capture, no AV evasion.
  8. Shared component: deps\RinkApi.dll (sha256 14d99d29…) is the same file shipped by mod 3802863574 "Arena Loader"; both mods therefore emit the same heartbeat. Assessed once, here.

Bottom line #

Feature-rich but not malicious: it is a league-rules gameplay mod that additionally ships an always-on analytics pipeline — SteamIDs, names, playtime and stored per-player settings to rinkpuck.com, plus skin images and scoreboard data pulled from the same site — with no way to switch it off. Install if you trust the author's backend; block rinkpuck.com and rinkbot.erscup910.workers.dev if you don't.
