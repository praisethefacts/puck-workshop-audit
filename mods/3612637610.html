What it is #

A replay recorder and player for Puck. It records a match into a compact custom binary file (.prp), then lets you browse, play back and delete recordings from an in-game menu — re-spawning players, sticks and the puck from the recorded event stream while a separate camera follows the action.

The DLL is the entire mod; there are no assets, no native code, no scripts.

Code analysis #

Bootstrap. Replay/ReplayMod/Plugin.cs implements IPuckPlugin; OnEnable() instantiates a Harmony and calls PatchAll(), OnDisable() calls UnpatchSelf(). Recording and playback are driven through CustomReplayRecorder, CustomReplayPlayer, CustomReplayManager and AdvancedReplayEngine.

Harmony patches — 9, all read-only or protective. PatchCursorDuringReplay.cs:6 (UIManager.CheckMouseRequirement), PatchDisableScoreboardUpdates.cs:10 and :34 (UIScoreboard.AddPlayer / RemovePlayer), PatchProtectPuckSpawning.cs:9 and :33 (PuckManager.Server_SpawnPucksForPhase / Server_SpawnPuck), PatchProtectReplayStop.cs:9 and :32 (ReplayPlayer.Server_StopReplay / ReplayRecorder.Server_StopRecording), PatchReplayCameraFollow.cs:11 (ReplayCamera.OnTick), PatchStickPhysicsDuringReplay.cs:7 (Stick.FixedUpdate), UIChat_AddChatMessage_Patch.cs:7 (UIChat.AddChatMessage). Their purpose is to stop the game from tearing down replay state or spawning extra pucks while a replay is being scrubbed — they suppress game actions, they do not add any outbound behaviour.

Network — no network APIs of any kind. There is no HttpClient, WebClient, WebRequest, UnityWebRequest, Socket, TcpClient, UdpClient, named pipe or Steam API call in any of the 67 source files; evidence/api_surface.txt has no [Network] section at all for this mod. Replay data is stored and played back entirely on the local machine. No URL, hostname or port appears in the code.

Filesystem — contained and predictable.

  • Replay files: ReplayBinarySerializer.cs:95 File.WriteAllBytes(filePath, array), read back at :113 File.ReadAllBytes(filePath) / :154 FileStream(filePath, FileMode.Open, FileAccess.Read).
  • Location: CleanStorageHelper.cs:21–:26 → Application.persistentDataPath/Replays on a client, or <server root>/Replays on a dedicated server; *.prp only.
  • Retention: CleanStorageHelper.CleanStorage(int limitMB) lists *.prp in that folder only, and when the total exceeds the user's configured limit deletes the oldest files until it is under budget (ClearStorageHelper.cs:34 Directory.GetFiles(empty, "*.prp", SearchOption.TopDirectoryOnly)).
  • Manual delete: ReplayMenu.cs:704 File.Delete(replay.FilePath) — only the selected replay.
  • Settings: ModSettings.cs:74–:77 → <game>/config/<ConfigurationFileName>, JSON via System.Text.Json (:38 Deserialize, :51/:68 File.WriteAllText).
  • Nothing is written to Documents, Desktop, AppData, temp, or outside the two paths above.

Serialization is hand-rolled, not dangerous. ReplayBinarySerializer is a bespoke format: a magic int 1347571712 and version 3 (:216–:217), then per-event tick/type-byte/length-prefixed payload, dispatched by an explicit switch on the known event-type name (:583). There is no BinaryFormatter, no SoapFormatter, no type-name-driven Type.GetType deserialization, no XmlSerializer of attacker-chosen types — i.e. none of the classic .NET deserialization-RCE patterns. Bounded reads: strings are ushort-length-prefixed (ReadStr at :1006–:1009) and event payloads are ushort-length-prefixed (:557–:558), so a crafted .prp cannot request a multi-GB allocation through those fields.

Process execution — two fixed, benign uses, both user-clicked.

  1. ReplayMenu.cs:618 Process.Start("https://steamcommunity.com/profiles/" + replayHeader.RecorderSteamId) — clicking the recorder's name opens their Steam profile in the default browser. The string is hard-prefixed with the https://steamcommunity.com/profiles/ URL, so the shell handler treats it as a URL, not a file.
  2. ReplayMenu.cs:679–:684 Process.Start(new ProcessStartInfo { FileName = "explorer.exe", Arguments = "/select,\"" + fullPath + "\"", UseShellExecute = true }) — the "Open containing folder" context-menu item.

Reflection — 4 private-field reads, all game types. AdvancedReplayEngine.cs:667 typeof(UIChat).GetField("chatMessageAsset", Instance|NonPublic); PatchStickPhysicsDuringReplay.cs:10/:12 typeof(Stick).GetField("rotationContainer"/"bladeAngleStep", NonPublic); ReplayMenuAccessButtons.cs:14 typeof(UIMainMenu).GetField("settingsButton", NonPublic). These are read-only UI/physics handles required by the replay rendering; nothing is written and no code is generated.

Absent categories (checked against evidence/api_surface.txt and all 67 sources). No network APIs of any kind. No registry access (no [Registry] category, no RegistryKey/Microsoft.Win32 anywhere). No crypto (Aes/Rijndael/CryptoStream) and no base64. No Assembly.Load/Assembly.LoadFrom/Emit/dynamic code loading. No P/Invoke, no DllImport, no Marshal. No input capture (GetAsyncKeyState, clipboard), no screen capture. No credential, token, session or cookie access — GetAuthTicket never appears. No Steamworks API. No persistence (no Run key, no scheduled task, no service, no startup entry). No AV/AMSI/ETW evasion, no obfuscation, no anti-debug, no environment fingerprinting.

Findings #

  1. Launches the default browser with a Steam profile URL built from replay metadata (ReplayMenu.cs:618). Only reachable by clicking the recorder's name in the replay list; the URL prefix is hard-coded so the target host cannot be redirected to an arbitrary file or site. Severity: low.
  2. Launches explorer.exe /select,"<path>" (ReplayMenu.cs:679–:684) for "Open containing folder". Standard shell invocation, path comes from the mod's own replay list (Path.GetFullPath(replay.FilePath)). Severity: low.
  3. Automatic deletion of old replay files (CleanStorageHelper.cs, CleanStorage(int limitMB)). When the user-configured size limit is exceeded, the oldest .prp files in the Replays folder are deleted without further prompting. It is strictly scoped — SearchOption.TopDirectoryOnly, "*.prp" glob, only its own folder — but a user who expects recordings to persist should know. Severity: low (by design, user-configurable).
  4. Nine Harmony patches on game methods including UIScoreboard.AddPlayer/RemovePlayer and Stick.FixedUpdate. Replay support genuinely requires suppressing live-game state updates while scrubbing; the patches only skip game calls. This is the normal cost of this kind of mod, and the reason a replay mod must be installed by everyone in the lobby for a match to look identical. Severity: informational.
  5. Unsigned, private-field reflection into UIChat/Stick/UIMainMenu (AdvancedReplayEngine.cs:667, PatchStickPhysicsDuringReplay.cs:10/:12, ReplayMenuAccessButtons.cs:14). Fragile across game builds (the mod breaks rather than misbehaves on a version bump), but not a security issue. Severity: informational.

Evidence trail #

  • Method: SHA-256 inventory (evidence/inventory.tsv, evidence/hashes_sha256.txt), PE header parsing (evidence/pe_info.txt), ilspycmd decompilation of the single managed DLL into 67 C# files (sources/Replay/), automated magic-signature/keyword scan (evidence/scan_hits.tsv — 1 hit: the MZ at offset 0 of the DLL itself; hits_summary.txt — 0 magic, 0 keyword), full-source pattern review plus api_surface.txt cross-check.
  • Read in full: ReplayBinarySerializer.cs (all 1,000+ lines of format/serialisation logic), CleanStorageHelper.cs, ModSettings.cs, ReplayMenu.cs (lines 600–724), and the Harmony patch classes.
  • Keyword roll-up across every .cs: http/HttpClient/WebClient/Socket — none; Registry — none; Assembly.Load — none; FromBase64String — none; GetAuthTicket — none; Clipboard — none; GetAsyncKeyState — none; DllImport/Marshal. — none; Aes/Rijndael/CryptoStream — none; DownloadFile/DownloadString — none; Steamworks — none; powershell/schtasks/RunKey — none. Matches for Process.Start, File.Delete, File.WriteAllBytes are all the lines cited above.
  • What could NOT be verified: the binary replay format was read statically but no malformed .prp was fuzzed, so the mod's robustness against a deliberately corrupted replay file was not tested (the length-prefix bounds make a memory-exhaustion issue unlikely but not impossible if a count field such as the event count at :551 is attacker-controlled). Replay playback was not executed in-game — the game was not run. No REA binary note exists for this DLL.

Bottom line #

Keep. It is a self-contained replay recorder: it writes and reads its own .prp files under the game's persistent data folder, opens a browser or Explorer only when you click the corresponding menu item, and contains no network client, no registry access, no crypto and no persistence. The one thing to know is that it will silently delete your oldest recordings when they exceed the storage limit you set.
