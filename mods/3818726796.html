What it is #

A UI-only scoreboard replacement ("GPM Tab") for Puck that draws a Global Puck Masters league tab, a HUD, goal/announcement cards, intro/end cards, a jumbotron overlay and a shootout UI. When the current server name is recognised by the GPM website it also shows the league match context (division, round, series, team colours/logos). Toggled in-game with F6, off-state stored in PlayerPrefs key gpm_tab_off.

Everything it renders is client-side: no gameplay state is modified, no server authority is taken, and nothing about players is uploaded.

Code analysis #

Bootstrap — Plugin.cs:7 GpmTab.Plugin : IPuckPlugin, plugin id com.globalpuckmasters.tab (:9), version 0.12.0 (:11). OnEnable (:31-57) first guards against a duplicate copy already in the process (GameObject.Find), then branches on SystemInfo.graphicsDeviceType == 4 (:36) — on a dedicated server (Null graphics device) it spawns only ServerRunner and returns, so no UI is ever built there. On a client it creates one Harmony("com.globalpuckmasters.tab") instance and a DontDestroyOnLoad runner object (:44-47). OnDisable (:59-86) tears the runner down, destroys the host object, calls UnpatchSelf() and Feed.Reset(true).

Harmony usage — this is the most unusual part of the mod and worth stating precisely: the assembly contains no [HarmonyPatch] attributes at all. The only patch it installs is a read-only postfix on another mod's method: Feed.cs:61-100 scans AppDomain.CurrentDomain.GetAssemblies() for an assembly whose name contains PuckMod_Stats, resolves type Codebase.NetworkCommunication and its static (string, string) GetData(ulong), then Feed.cs:86 harmony.Patch(methodInfo, null, new HarmonyMethod(GetDataPostfix), null, null, null). GetDataPostfix (Feed.cs:102-115) ignores every call except clientId == 0 and parses the returned key/value text with regexes (stats(SOG|SAVEPERC|BLOCK|PASS|HIT|TAKEAWAY|TURNOVER|PLUSMINUS)(\d{17})$, statsBATCH…, statsSTAR, statsRESETALL, Feed.cs:20-24, :117-140) into an in-memory PStats dictionary. It never alters the return value and never writes back, so the only effect is "GPM tab displays extra stats when the stats mod is present". If the stats mod's reader has a different shape it logs a warning and leaves the fields empty (Feed.cs:79-84).

Game reads are reflection only — no game method is patched by GPM itself; it reads fields/properties: UIView.View (BandUi.cs:83), UIGameState.phaseLabel/timeLabel (GameTexts.cs:27,29), UIView.View+UIAnnouncements.announcements (GoalUi.cs:116-118), UIGameState.gameState (HudUi.cs:243-245), UIScoreboard.scoreboard/nameLabel/playersLabel (TabUi.cs:767-779). All read-only.

Findings #

  1. Single network host, read-only. globalpuckmasters.com/api.php is queried by GET with the server name only (MatchInfo.cs:31,40). No POST, no analytics, no SteamID — nothing personal leaves the machine.
  2. Team logos are fetched from API-supplied URLs. MatchInfo.cs:130-175 accepts any http… URL from the API response and downloads it into a texture. A hostile/compromised API response could make the client request an arbitrary URL (a request to a third party, and a way to confirm the client is running). Impact is limited to an image decode — the bytes are never written to disk and never executed.
  3. Patches another mod, not the game. The only Harmony patch is a postfix on PuckMod_Stats's Codebase.NetworkCommunication.GetData (Feed.cs:86) that observes and never modifies the result; all game access is reflection reads.
  4. All UI state is client-local. F6 toggle in PlayerPrefs (gpm_tab_off), temp font cache under Application.temporaryCachePath/gpm-tab-0.12.0, and two debug-only PNG exports gated behind a <cwd>/gpm_tab_debug.txt file.
  5. Dedicated servers get no UI at all. Plugin.cs:36 short-circuits on the Null graphics device and runs only Sync.Tick() (ServerRunner.cs:5-10), so the tab never tries to render server-side.
  6. Automated scanner hits are benign. The 5 binary "hits" are its own MZ header plus MZ/ZIP/7Z byte patterns inside the embedded font/PNG resources; 0 text hits, no flags.
  7. No update mechanism. Unlike some sibling mods it never touches Steam Workshop APIs — no self-update, no subscribe/download calls.

Bottom line #

A cosmetic league scoreboard. It phones exactly one website (globalpuckmasters.com) with a plain GET containing the server name, downloads team logos from URLs that site hands back, and otherwise only reads game UI state by reflection and talks to the match over Netcode. No credentials, no persistence, no code loading, no uploads. The only thing to keep in mind is that it will make a network request to whatever logo URL the league API names — harmless as an image decode, but not something you'd want on an air-gapped box. Safe to install.
