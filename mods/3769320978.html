What it is #

A referee-mode UI for Puck. When the local player is in spectator camera, pressing F7 opens a draggable panel with faceoff-spot, penalty, game-call, stoppage and player-list controls, plus a small options panel; the buttons type the corresponding referee commands into the game's own chat command channel.

It ships one DLL plus one Unity AssetBundle containing the UXML/USS/panel-settings/texture for the UI.

  • DLL: RefModeUI_Mod.dll, 38,912 B, sha256 ad57fd1dacdfa60e1c77f8df0b5e5418803a540e43fe8ac4188133bff28322b3, managed .NET (dotnet=1), unsigned, PE32 i386, subsystem CUI, 3 sections (.text/.rsrc/.reloc), overlay 0, entropy 5.43 — normal compiled .NET assembly, not obfuscated (18 source files / 20 types, fully readable C#).

Code analysis #

Bootstrap. RefModeUI_Mod/RefModeUI.cs implements IPuckPlugin and is the only entry point. OnEnable() returns immediately on a dedicated server (IsDedicatedServer() = SystemInfo.graphicsDeviceType == 4), otherwise creates a DontDestroyOnLoad GameObject("RefModeUI_Manager") with UIManager, calls harmony.PatchAll(), and subscribes to the game's "Event_OnSceneLoaded". The UI is loaded when Scene.buildIndex == 2 (the play scene) and unloaded otherwise. OnDisable() calls harmony.UnpatchSelf().

Harmony patches — 2, both UI/input only. RefModeUI.cs:13 [HarmonyPatch(typeof(PhysicsManager), "Update")] with [HarmonyPriority(600)] inner class PhysicsManagerUpdateClientPatch — a postfix that only reads Keyboard.current (f7Key.wasPressedThisFrame toggles the panel when CanShowRefUI() is true, altKey.wasPressedThisFrame releases UI input focus). CanShowRefUI() requires a live camera whose (int)Type == 7 (spectator). Second patch RefModeUI.cs:63 [HarmonyPatch(typeof(CameraManager), "SetActiveCamera")] postfix that closes the panel when the new camera type is not 5/6/7. Neither touches physics state or game rules.

Network — no network APIs of any kind, and no netcode use either. There is no HttpClient, WebClient, WebRequest, UnityWebRequest, Socket, TcpClient, UdpClient or Steam API call in the 18 files, no URL, no hostname, no port. Notably, Constants.cs declares FROM_SERVER_TO_CLIENT = "RefModeUI_server", FROM_CLIENT_TO_SERVER = "RefModeUI_client" and ASK_SERVER_FOR_STARTUP_DATA = "RefModeUIASKDATA", but nothing in the mod ever uses them — a full-tree search finds no CustomMessagingManager, SendNamedMessage or RegisterNamedMessageHandler call. Those constant names are leftovers (likely copied from the author's other framework plugin) and the 10-mod scan's [Network]-adjacent keyword roll-up is therefore also a false trail.

How a referee call actually leaves the mod. RefModeUI_Mod.Game/ChatCommandSender.cs is the whole mechanism: public static void Send(string message) { Logging.Log("Sending: " + message); NetworkBehaviourSingleton<ChatManager>.Instance.Client_SendChatMessage(message, false, false); }. It types the command into the game's own chat channel, which means the game server's own command validation decides whether it happens — the mod has no private command channel and cannot bypass the server.

Filesystem — read-only, one local bundle; UI state in PlayerPrefs.

  • UIManager.cs:12 pluginDir = Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location), :14 bundlePath = Path.Combine(pluginDir, "AssetBundle", "refuimenu"), :89 if (!File.Exists(bundlePath)) then :94 AssetBundle.LoadFromFile(bundlePath) — the mod loads its own shipped bundle from its own folder. It then pulls its own named assets: :100 LoadAsset<VisualTreeAsset>("assets/refmodeui.uxml"), :101 PanelSettings, :102 StyleSheet, :117 LoadAsset<Texture2D>("assets/hockey_rink.png"). No remote bundle, no download, no file writes.
  • UI preference: UIManager.cs:115 _isLightTheme = PlayerPrefs.GetInt("RefModeUI_LightTheme", 0) == 1; and :335–:336 PlayerPrefs.SetInt(...) / PlayerPrefs.Save(). One boolean.
  • Nothing is written to disk by the mod itself: no config file, no log file, no cache.

Absent categories (checked against evidence/api_surface.txt and all 18 sources). No network APIs of any kind. No direct registry access — no [Registry] category, no Microsoft.Win32; the only registry-touching chain is Unity's own PlayerPrefs (UIManager.cs:335) which persists a single boolean through Unity's player-prefs store (on Windows under HKCU\Software\<company>\<product>). That is Unity API usage for one theme flag, not the mod touching the registry. No crypto and no base64. No serialization of external data at all ([Serialization] absent). No Assembly.Load/LoadFrom/Emit except the asset-bundle load above (data, not code). No P/Invoke, no DllImport, no Marshal. No clipboard, no screen capture; keyboard reads are the two Keyboard.current property reads in the Update postfix and go nowhere. No credential/token/session access, no Steamworks API. No persistence beyond the PlayerPrefs flag. No AV/AMSI/ETW evasion, no obfuscation, no anti-debug, no environment fingerprinting.

Findings #

  1. Referee commands are sent as ordinary game chat via the game's own client API (ChatCommandSender.cs:8 NetworkBehaviourSingleton<ChatManager>.Instance.Client_SendChatMessage(message, false, false)). This is the safest possible design: whatever the server accepts from a normal player, it accepts here — no privileged side channel, no client-trusted command path. Severity: informational (positive).
  2. Loads a local, self-shipped Unity AssetBundle (UIManager.cs:14/:94) — path is Assembly.GetExecutingAssembly().Location + AssetBundle\refuimenu, i.e. the mod's own Workshop folder. A missing/unreadable bundle is handled (:89), and every asset name it requests is a fixed string. No remote or user-supplied bundle can be injected into that path. Severity: low.
  3. Two Harmony postfixes on PhysicsManager.Update and CameraManager.SetActiveCamera (RefModeUI.cs:13, :63). They read the keyboard and toggle/close the panel; they do not alter physics or camera state. Per-frame cost is negligible. Severity: informational.
  4. One UI preference written through Unity PlayerPrefs (UIManager.cs:335–:336). Single boolean light-theme flag, stored in Unity's own prefs store. Severity: informational.
  5. Unused network-related constants (Constants.cs: FROM_SERVER_TO_CLIENT, FROM_CLIENT_TO_SERVER, ASK_SERVER_FOR_STARTUP_DATA) with no corresponding code. Leftovers, not a dormant channel — but worth recording so a future keyword scan does not flag this mod again. Severity: informational.
  6. The 10 automated signature hits inside AssetBundle\refuimenu are false positives (offsets 3415, 11518, 27141, 31283, 32883, 138982, 140793, 142375, 165568, 182504). They sit inside the compressed serialized bundle; hits_summary.txt records keyword hits: 0 and text hits: 0. Severity: informational (scan artefact).

  • What could NOT be verified: the AssetBundle was hashed and signature-scanned but not unpacked and inspected asset-by-asset (the DLL only ever requests the four fixed asset names listed above, so an unrequested extra asset would be inert). Bottom line #

Keep. It is a self-contained spectator UI: it loads one locally shipped asset bundle from its own folder, remembers one theme flag, reads F7/Alt, and types referee commands into the game's normal chat channel so the server's own validation still applies. No network client, no registry writes, no crypto, no process execution, no persistence — the "network" constants in its source are unused leftovers.
