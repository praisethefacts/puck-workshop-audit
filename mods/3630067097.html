What it is #

A penalty-shootout / mini-game mode for Puck. It takes over the game state machine, positions shooters and goalies, scores individual attempts, runs an order-vote system, and draws its own HUD and menus. It ships a config example pair, a banner image and a whistle sound effect alongside the DLL.

The DLL is required; the .json files are example configs for server owners, and the .wav/.png are cosmetic.

  • DLL: ShootoutMod.dll, 198,144 B, sha256 145543f5783d6ee646c667b537b2a7b7c7a34929b43ec9e2e5398f98c4e235fd, managed .NET (dotnet=1), unsigned, PE32 i386, subsystem CUI, 3 sections (.text/.rsrc/.reloc), overlay 0, entropy 5.75 — normal compiled .NET assembly, not obfuscated (29 source files / 37 types, readable C# with real names).

Code analysis #

Bootstrap. PoncePuck.Shootout/ShootoutPlugin.cs + ShootoutMod.cs implement IPuckPlugin; OnEnable() creates a Harmony, patches, and initialises a UI game object; OnDisable() unpatches and tears down. On a dedicated server (Application.isBatchMode) the UI paths are skipped (ShootoutMod.cs:75, :81, :87, :128).

Harmony patches — 5 game methods. Puck_OnCollisionEnter_Patch.cs:7 (Puck.OnCollisionEnter), BaseGameMode_ScoreGoal_Patch.cs:9 ([HarmonyPatch] / target resolved by attribute arguments), ShootoutMod_GameManager_Server_SetGameState_Patch.cs:9 (GameManager.Server_SetGameState), ShootoutMod_UIScoreboard_AddPlayer_Patch.cs:9 (UIScoreboard.AddPlayer), CustomCommandUnknownCommandPatch.cs:8 (the game's unknown-slash-command handler, to add mod commands). These are the mechanism by which the mod runs its own game phase — expected for a game-mode mod, and they only alter game state, not OS behaviour.

Network — two netcode surfaces, both narrow and both already present in the game's session.

  • Server side (ShootoutMod_NetworkHandlers.cs:14 HandleClientMessage) accepts exactly three client messages: "ShootoutModAskStartupData", "ShootoutModAskShootoutState", and "ShootoutModSubmitOrderVote" (an index array clamped to 0–32 at :36–:43 before use). There is no client command-execution channel: no arbitrary command strings are accepted from clients, no admin actions are triggered remotely.
  • Client side (HandleServerMessage at :60) parses "ShootoutModStartupData" (version string, warns on mismatch with 3.0.0) and "ShootoutModShootoutState" (a Dictionary<string,object> from JSON that only drives the mod's own HUD, :80–:88).
  • There is no HttpClient, WebClient, WebRequest, Socket, TcpClient, UdpClient or Steam API call anywhere. The only UnityWebRequest in the mod is ShootoutUI.cs:1647 UnityWebRequestMultimedia.GetAudioClip("file:///" + filePath, AudioType 20) — a local file audio loader for Whistle.wav, not a network request.
  • The only external URL is ShootoutSettingsUI.cs:427 Application.OpenURL("https://buymeacoffee.com/amikiir") (the author's tip jar button, user-clicked). No data is sent with it.

Admin authority is delegated to the game, not invented. AdminRegistry.cs:38 IsAdminSteamId(string) and :70 IsAdminPlayer(Player) resolve admin status through the game's own AdminManager.IsSteamIdAdmin(...) (:53) after normalising the SteamID. ShootoutController.cs:4335/4340/4349 uses that. So a client cannot promote itself; whatever the server's real admin list says, applies.

Filesystem — two config files, plus one shared menu registry.

  • Server config: ShootoutConfigManager.cs:44–:51 → <server root>/config/shootout_config.json; read :98, written :117.
  • Client config: ShootoutConfigManager.cs:54–:88 → <game root>/config/ModHub/shootout_client_config.json; read :132.
  • Shared PonceMods menu registry: PonceMods.Shared/ModMenuHub.cs:83–:88 → Application.persistentDataPath/PonceMods/PonceMods_ModMenuHub.json, read :361 File.ReadAllLines, written :394 File.WriteAllLines, deleted :429 File.Delete when empty. This is a local registry of installed Ponce-family mods so they can share one menu button.
  • Every path above is inside the game's own tree or Unity's persistent data folder. Nothing touches Documents, Desktop, browser profiles, or other applications' data.

Reflection — used only to find sibling mods' menus. ModMenuHub.cs:177 reads _localCallbacks via non-public reflection, :209/:268 read _localRunner, :217/:276 read the IsPrimary property, :221 invokes OpenModPanelPublic. MaxPractice/CompetitiveAdjustments (same author family) contain the matching PonceMods.Shared.ModMenuHub type, which is what this is looking for. Read-only access to private fields of a known type; no code generation, no dynamic assembly loading.

Absent categories (checked against evidence/api_surface.txt and all 29 sources). No HTTP/network client, no socket, no URL upload, no Steam API call. No Windows registry access — the three [Registry] lines in api_surface.txt are ShootoutController.cs:4335/4340/4349 referencing the mod's own class AdminRegistry, which is a SteamID allow-list wrapper, not Microsoft.Win32. No AV/AMSI/ETW evasion, no obfuscation, no anti-debug. ShootoutController.cs:547 new Random(Environment.TickCount ^ (int)DateTime.UtcNow.Ticks) is a gameplay RNG seed, not cryptography.

Findings #

  1. Client→server message surface is three whitelisted messages, none of which executes commands (ShootoutMod_NetworkHandlers.cs:24–:52). The only client-controlled input reaching server logic is a vote array that is range-clamped before use (:36–:43). Good design; nothing to exploit for privilege escalation. Severity: informational (positive).
  2. Opens the author's tip-jar page in the default browser on click (ShootoutSettingsUI.cs:427, https://buymeacoffee.com/amikiir). No query parameters, no data attached. Severity: low.
  3. Loads Whistle.wav through UnityWebRequestMultimedia (ShootoutUI.cs:1647, "file:///" + filePath). Looks like a network call in a keyword scan but is a local file:// URI with no host component. Severity: informational.
  4. 34 automated "magic signature" hits are false positives. 16 are MZ/ZIP/7Z byte sequences at scattered offsets inside preview.png (offset 51173 MZ, 108583 ZIP, 161014 7Z, …, 343350 7Z — normal for compressed PNG data), one is ShootoutMod.dll 0 MZ (the DLL's own header), and one is a raw https:// ASCII run at offset 75 inside Whistle.wav (audio sample bytes that happen to spell it; no code reads it). hits_summary.txt: keyword hits: 0, zero text-pattern hits. Severity: informational (scan artefact).
  5. Writes a shared mod-menu JSON in Unity's persistent data path (ModMenuHub.cs:83–:88) and reads it back. It records installed Ponce mods/menu entries; no user or account data. Severity: low.
  6. Five Harmony patches on core game methods, including GameManager.Server_SetGameState and UIScoreboard.AddPlayer. Necessary for a custom game mode; means the mod must be installed on both server and clients for consistent behaviour, and can break after a game patch. Severity: informational.

  • What could NOT be verified: runtime behaviour on a live server was not executed (game not run); the vote-aggregation and score logic were read statically only. The readme file (102 B) was not quoted; preview.png and Whistle.wav were hashed and scanned but not rendered/played. No REA binary note exists for this DLL.

Bottom line #

Keep. A well-behaved game-mode mod: its client-facing netcode accepts three fixed message types and no commands, admin checks go through the game's own admin list, it writes two JSON configs and one local menu registry, and it has no network client, no registry access, no crypto, no persistence and no download capability. The tip-jar link and the whistle sound are the only external-looking things, and both are inert.
