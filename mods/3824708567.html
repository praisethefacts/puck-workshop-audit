Verdict: BENIGN WITH CAVEATS - risk score 28/100. No malware. It is a genuine, unusually well-written in-game replay/recording studio for Puck. The only ways data leaves your PC are (a) optional and entirely self-configured Discord webhook posts, and (b) the game's own netcode, which ships clips to/from the game server you are already connected to. It has no hardcoded server, no downloader, no credential/wallet/browser access, no keylogging, no persistence and no obfuscation.

2. What it does #

CinemaPlugin (implements IPuckPlugin) creates a GameObject("APPLCinema") with a Recorder component. It records every frame of the game view into RAM (ring buffer keyed by Time.realtimeSinceStartup), detects goals/saves/shot moments from the game's own events and PlayerCustomizationState state, and keeps clips plus full-game replays as .puckclip / .puckgame files (GZip-compressed custom containers, ClipIO / GameWriter / GameReader).

The F7 Studio is a full editing UI: a custom UI toolkit (no Unity UI), 10 director cameras with keyframed paths/predictive tracking, matte/scope/vertical framing, a render queue and thumbnails. Rendering is done two ways: a Windows Media Foundation MP4 writer (Mp4Writer, the 9 DllImports into ole32/mfplat/mfreadwrite - all documented MF sink-writer APIs) or, if available, a locally installed ffmpeg (found only via config / PATH / WinGet - never downloaded).

Two optional distribution paths:

  • Discord webhook (cfg.Webhook, empty by default): multipart POST of the clip file + highlight metadata to <webhook>?wait=true, 3 retries with Retry-After handling, and a self-test that posts and then deletes its own test message. Accepted only if the URL both starts https:// and contains /api/webhooks/ (Settings.HasWebhook).
  • Game netcode (Courier): Unity Netcode CustomMessagingManager named messages "APPLCinema.Hello" / "APPLCinema.Clip". A client sends Hello when it connects (only if receive_clips is on); the server then ships that player their own clips in 8192-byte pieces, 0.2 s pacing, max 4 MiB per clip, max 8 transfers open. Received clips are validated (Parcel.SafeName: no separators / .. / : and must end .puckclip), parsed with ClipIO.Read, then saved into the clips folder. Nothing received is executed or rendered automatically.

Ports.Free() / FirstFree() only probe whether a UDP/TCP port is free, used by a Harmony patch (appl.cinema.practiceport) that shifts the Practice server port if the configured one is taken. It never opens a listener.

4. Findings #

  1. (Medium-low) Optional upload of your clips to a Discord webhook. Off by default ("webhook": ""). If you paste a webhook URL, clips - including in-game player names / SteamIDs of everyone in the clip - are uploaded there. Validation only requires https:// + /api/webhooks/, so a Relay/hijacked URL would also pass; treat it like a password. This is a feature, not malware, but it is the single data-exfiltration path in this mod.
  2. (Low) A game server can push clip files onto your disk while you are connected (receive_clips defaults to true). Each file is capped at 4 MiB, name-validated, parsed before saving, and never auto-executed; worst case is junk files in your clips folder.
  3. (Low) It reads your Downloads folder (top level only, *.puckclip / *.puckgame) plus any clip_folders you configure, to import clips. File names are shown in the UI/log. Nothing else in that folder is read.
  4. (Low) ffmpeg execution. Rendering can launch whatever ffmpeg.exe it finds first (config path -> PATH -> %LOCALAPPDATA%\Microsoft\WinGet). If something already replaced ffmpeg on your machine, that binary would run - keep normal AV/software hygiene. It does not fetch ffmpeg itself.
  5. (Info) In-process modifications. Harmony patch + reflection into game internals (ServerManager.StartHost, EventManager, GoalTrigger, PlayerCustomizationState) - normal for Puck mods, but combined with unsigned binary + Steam auto-update it means the code can change under you at any time.
  6. (Info) Provenance. Created and updated same day, 20 subscribers, brand-new item. The author claims a companion server mod 3824593782; that item is not installed here and was not audited. If you run it, audit it separately (it is the server-side half that stores/serves clips).

6. Bottom line #

Not malware. Keep it if you actually use the clips/studio; otherwise it is dead weight. It is one of the cleanest mods in this collection code-wise: no hidden network endpoints, no credential access, no persistence, no obfuscation. Before relying on it:

  • leave "webhook": "" empty unless you control the Discord channel;
  • set "receive_clips": false if you do not want servers able to drop files into your clips folder;
  • keep keep_games modest - recordings are large and pruned only from its own folder;
  • remember it only captures the game view, never your desktop.
