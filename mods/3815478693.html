What it is #

A server-side "PUG" (pick-up game) manager for Puck by the author of Rink and Arena Loader (build B14). On a server whose name starts with RINK | PUG #<n> it fetches that pug's roster from the author's Cloudflare Worker, enforces team and position assignment from the roster, holds the match in warm-up until the listed players are seated, and records per-player match statistics (shots, hits, saves, faceoffs, time on ice, "OVR" rating) plus a positional replay. All of that is then POSTed to the author's stats backend at rinkpuck.com, keyed by a hardcoded shared API key. There are 8 Harmony patches, all gameplay/statistics or roster enforcement, and no local file writes beyond a temporary .glb export that is read and immediately deleted.

Code analysis #

Bootstrap. RinkPugs.Plugin : IPuckPlugin (Plugin.cs:7), Harmony id com.rink.pugs (:11). OnEnable calls Harmony.PatchAll(), StatsTracker.Init(), then creates DontDestroyOnLoad("RinkPugs") with StatsTickBehaviour and PressureBehaviour (:22-28); OnDisable shuts the tracker down and UnpatchSelf() (:38-48).

Harmony patches (8 targets, all benign gameplay/roster plumbing). GoalNetCollider.OnCollisionEnter postfix feeds shot-on-goal detection (GoalNetColliderEnterPatch.cs:6-20); PlayerBody.Server_OnCollisionDeferred prefix for hit detection (PlayerBodyHitPatch.cs:8-27); Player.Client_RequestClaimPositionRpc to block claiming a position outside your roster role (PlayerClaimPositionPatch.cs:8, uses PugRoster.IsPositionClaimBlocked); Player.Client_RequestTeamRpc to block joining the opponents' team when a roster is active (PlayerRequestTeamPatch.cs:8,22); PlayerManager.RemovePlayer to keep stats bookkeeping (PlayerManagerRemovePlayerPatch.cs:7); Puck.OnCollisionEnter/OnCollisionExit for shot/pass/possession events (PuckCollisionEnterPatch.cs:7, PuckCollisionExitPatch.cs:7); PublicGameMode<PublicGameModeConfig>.OnWarmupTimedOut prefix that re-arms warm-up while the roster is incomplete, announcing why (WarmupHoldPatch.cs:7-35, StartGate.cs:27-…). None of these touch auth, Steam, file, process or network APIs.

Network — two author-controlled endpoints.

  1. PugRoster.Fetch GETs https://rinkbot.erscup910.workers.dev/pug-roster?pug=<n> every 60 s (15 s while no roster) and parses {blue:[…],red:[…]} — items may be SteamID strings or {sid,name,role} objects (PugRoster.cs:12,41-146). This is the roster used for team/position enforcement and the start gate.
  2. RinkApi.Post POSTs JSON to https://rinkpuck.com/api/stats with header x-rink-key: iZIcx2y-h29cC2GNes4SI03qtNSrK8vh (hardcoded, RinkApi.cs:11-13,59). It uses a plain System.Net.Http.HttpClient (:15) off the main thread with retry backoff 3/10/30/60 s for match_start/match_end/replay; failure only logs a warning (:27-52). Every payload carries time = DateTime.UtcNow in ISO-8601 (:25).

Actions actually sent (all gated by PugInfo.IsTrackedServer, i.e. NetworkManager.Singleton.IsServer and server name starting RINK | PUG # — PugInfo.cs:8-35):

  • goal — matchId, scorer SteamID + name, score, period, strength (StatsTracker.cs:590-603);
  • match_start — matchId (:1027-1034);
  • live — every 15 s or on phase change: matchId, period, tick, score, pressure + pressure history, and a per-player array of SteamID, username, team, goals/assists/±/shots/hits/blocks/takeaways/giveaways/posts/passes/faceoffs/time-on-ice/shifts/possession/top speed/max shot speed/hits received/saves/shots against/OVR (StatsTracker.cs:424-427,1122-1190, LiveState.cs, LivePlayer.cs);
  • match_end — full _match.Players stats dictionary, team stats, goal list, pressure history, pug number, winning team (:1097-1110);
  • replay — ReplayRecorder.Snapshot: matchId, 5 Hz flag, player list (sid, name, team, number) and up to 12,000 frames (0.2 s apart, ~40 min) each containing rounded position/rotation for every skater plus the puck, and ReplayModels.Payload() — base64 GLB exports of one skater body, one goalie body and their sticks (ReplayRecorder.cs:118-227, ReplayModels.cs:34-155).

Local filesystem — temporary only. ReplayModels.Export writes %TEMP%\rinkpugs_replay_model.glb via GLTFast, reads it into a base64 string, then File.Deletes it (ReplayModels.cs:111,140,150). That is the only file I/O in the mod (evidence/api_surface.txt [FileSystem] shows exactly these four lines). No other directory is created or touched.

Absent. No credential, session, cookie or Steam-auth-ticket access (SteamIDs and usernames are read from the game's Player objects and uploaded as plain identifiers); no registry; no process creation or shell; no DllImport/Marshal; no Assembly.Load of anything; no persistence; no crypto or file encryption of user data; no clipboard, keyboard or screen capture; no update/download of executables (the only URL serving data is a roster JSON).

Findings #

  1. Full match telemetry, including a positional replay, is uploaded to rinkpuck.com with a hardcoded shared key and no opt-out. The replay payload is the notable one: per-0.2-second positions and rotations for every player and the puck for up to ~40 minutes, plus base64-encoded GLB models of a player and sticks. It is gameplay data generated by the server, not personal files, and it is gated to servers that opt into the RINK | PUG # naming convention — but any player on such a server is recorded and their SteamID/name uploaded. Severity: moderate.
  2. Roster comes from rinkbot.erscup910.workers.dev (Cloudflare Worker, author-controlled) every 60 s; the parsed roster controls who may join which team, which position they may claim, and whether warm-up is held (PugRoster.cs:12,182-268, StartGate.cs:27-…). A compromised Worker could therefore gate/reject players on tracked servers but cannot execute code — the response is parsed as JSON strings only. Severity: low.
  3. Straightforward System.Net.Http.HttpClient with the shared static API key (RinkApi.cs:13,15,59-60) and retry-with-backoff; response status is checked, body ignored. No proxy, no host switching from config, no dynamic URL construction beyond the pug number. Severity: informational.
  4. All 8 Harmony patches are statistics/enforcement hooks, applied in OnEnable and removed in OnDisable; the only "game-blocking" behaviour is re-arming warm-up until the roster is complete (WarmupHoldPatch.cs:15-29). Severity: informational.
  5. Only transient file I/O: one temp .glb written, read, deleted (ReplayModels.cs:111-155). No config, no cache, no persistence. Severity: informational.
  6. Absent categories (checked against evidence/api_surface.txt and all 27 decompiled files): no registry, no process/shell execution, no P/Invoke or Marshal, no Assembly.Load/reflection-generated code, no persistence mechanism, no credential/token/cookie/keyboard/clipboard/screen access, no user-data encryption. The single [Process] hit is an unused using System.Diagnostics; in Properties/AssemblyInfo.cs:1. Severity: n/a.

  • Not verified: the live behaviour of rinkpuck.com/the Worker, retention of uploaded replays, and the in-game effect of the roster gate. No independent REA binary note existed for this mod at review time.

Bottom line #

A PUG-organising and stats-tracking server mod, not malware: it only talks to two author-run hosts, only uploads data generated on PUG-named servers, and executes no downloaded code. Caveat: on such a server it records and uploads everything — SteamIDs, names, full stat lines and a 5 Hz positional replay of the game — with a hardcoded key and no way for players to decline.
