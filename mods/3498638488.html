What it is #

A high-resolution art pack for Puck: replacement rink-ice textures (plain, dark, dark-lite, and two "Gafurix Arena" variants), net, puck colours, jersey torso/groin textures and leg-pad textures, plus the layered Photoshop templates used to author them. The pack is consumed through reskinpack.json, so the game itself only ever reads a JSON manifest and PNG images.

The three .jsx files are Photoshop action recordings (the "Switcher Scripts") that recolour a rink PSD into dark / dark-lite / white variants. They are for the modder's own Photoshop session; the game never loads or executes them.

Code analysis #

There is no runnable code in this mod. No managed DLL, no native PE, no .exe, no .bat/.ps1, no Unity AssetBundle containing scripts.

reskinpack.json is a pure data manifest: name, unique-id (WABA_RealTextures), version 1.1.0, pack-format 1, and 27 reskins[] entries of the form {"type": …, "name": …, "path": …}. Types are rink_ice, net, puck, jersey_torso, jersey_groin, legpad — i.e. exactly the texture slots a reskin loader replaces. Every path is a relative path inside the pack (textures/rinks/…, textures/nets/…, textures/pucks/…, textures/jerseys/…, textures/legpads/…): no absolute paths, no .. traversal, no URLs, no script reference. The game-side loader decides what to do with those PNGs; nothing in this pack can ask it to load anything else.

The three .jsx scripts — read in full from the installed Workshop copy (see Evidence trail). All three have the same shape and are nothing but a recorded Photoshop action serialised to JavaScript:

  • hundreds of lines of charIDToTypeID("…") / stringIDToTypeID("…") identifier lookups plus new ActionDescriptor() / new ActionReference() / new ActionList() construction;
  • the only statements that do anything are executeAction(<id>, <desc>, DialogModes.NO) — e.g. Change to Dark.jsx:11,29,43,59,73,89,109,125,145,166,315,327 — representing layer selection by name (ref2.putName(idLyr, "White"), :21), hide/show of layer groups ("Hd ", :32), and layer-style/pattern-fill adjustments (patternFill, scale putUnitDouble(…, 51.000000), :299-315);
  • DialogModes.NO on every call means they run without prompting, but only inside Photoshop and only on the currently open document.

Controller-level ExtendScript was specifically searched for and is absent in all three files: no File(…) / Folder(…) / new File / .open() / .write() / .execute(), no eval / $.evalFile / app.doScript, no app.system / shell out, no Socket / http / download, no ExternalObject, no BridgeTalk, no document save/export/rename/delete. Greps for those patterns returned zero matches; the only non-descriptor token in the files is DialogModes, which is Photoshop's own enum.

Absent categories (checked against FACTS.md, inventory.tsv, scan_hits.tsv and the full JSX text): no DLL/PE/native code; no process creation or shell; no registry access; no persistence (no autorun, no startup entry, no service, no scheduled task); no network code or network-capable script API; no filesystem access from the scripts; no PowerShell/WScript/HTA; no crypto or obfuscated payload; nothing in the pack is auto-executed by the game — only reskinpack.json and the referenced PNGs are read.

Findings #

  1. No executable content at all. 0 managed DLLs, 0 native DLLs; the pack is PNG + PSD + JSON + TXT + three Photoshop scripts. Nothing in it is loaded as code by Puck.
  2. The .jsx files are inert action recordings. Only executeAction(…, DialogModes.NO) on PhotoShop descriptors; no File/Folder/eval/doScript/Socket/app.system calls. They cannot touch the disk or the network, and they only run if the user opens Photoshop and browses to them.
  3. reskinpack.json is data, not instructions. 27 entries, all relative in-pack PNG paths, no URLs, no absolute paths, no traversal.
  4. The size and entropy are art. 930 MB of 4K PNGs and layered PSDs; the "binary hits" in scan_hits.tsv (7,350) are MZ/ZIP/7Z byte patterns that occur naturally inside compressed PNG/PSD image data, and the http:// strings at PSD offsets 290–629 are XMP/ICC metadata blocks in the PSD header, not network code. 0 keyword hits, no automated flags.
  5. .psd templates are standard layered documents (rink 388 MB, leg-pads 55 MB, torso jersey 47 MB). They are authoring material; Photoshop-side risk is whatever the user's own Photoshop/plugins introduce, not this pack. One practical caveat unrelated to security: opening the 388 MB template on a low-RAM machine can exhaust memory.
  6. Nothing in the pack interacts with other mods or the game process. No loader DLL, no Harmony, no Steam API, no IPC — unlike the reskin-loader mods that this pack is meant to be used with.

Bottom line #

A big, legitimate HD texture and template pack. There is nothing executable in it: the game only reads a JSON manifest and the PNGs it points at, and the three Photoshop "switcher" scripts are just recorded action descriptors that select layers and tweak layer styles — no file, shell, eval or network access anywhere in them. Nothing here runs unless you deliberately load it in Photoshop, and even then it only edits the open document. Safe.
