What it is #

A very large goal-song and goal-horn replacement pack for Puck: 601 Ogg Vorbis files covering goal songs for individual NHL players/teams and goal horns for arenas. The single small DLL is the same oomtm450 "SoundsPack" framework plugin used by this author's other sound packs — it registers the tracks and synchronises the playlist with the game host so everyone in a lobby hears the same song.

The DLL is required; the .ogg files are inert audio data.

Contents #

  • 603 files / 134.73 MB, 1 folder: sounds\*.ogg × 601, sounds\settings.json (18,377 B), SoundsPack_PonceCustomGoalHornsPack.dll (40,448 B).
  • Example asset names: sounds\100_gecs_dumbest_girl_alive_goalsong.ogg, sounds\2pac_hail_mary_goalsong.ogg, sounds\2000edmonton_goalhorn.ogg.

Code analysis #

Bootstrap. oomtm450PuckMod_SoundsPack/SoundsPack.cs implements IPuckPlugin. OnEnable() warns if Application.version is not 1153 or 897 (SoundsPack.cs:103), calls _harmony.PatchAll() (:108), reads the server or client config (:115 / :120), and subscribes to Event_Everyone_OnClientConnected / Event_OnClientStopped. OnDisable() unregisters the named-message handler (:165) and calls _harmony.UnpatchSelf().

Harmony patches — exactly one. SoundsPack.cs:16 [HarmonyPatch(typeof(PhysicsManager), "Update")] with a [HarmonyPostfix] that, on a connected client, registers one named-message handler (:28) and then at most 12 times, 5 seconds apart, asks the host for the playlist (:31, :34). No game logic is altered.

Network — in-game netcode only, no internet transport. All traffic uses Unity Netcode's CustomMessagingManager — Codebase/NetworkCommunication.cs:52 SendNamedMessage(...) and :87 SendNamedMessageToAll(...). There is no HttpClient, WebClient, WebRequest, UnityWebRequest, Socket, TcpClient, UdpClient or any other outbound transport in the 27 source files, no URL, no hostname, no port, no DNS name anywhere in the code. Traffic stays inside the existing Steam/netcode lobby session and carries only the mod's playlist/metadata messages.

Filesystem — one config file inside the game folder. oomtm450PuckMod_SoundsPack.Configs/ClientConfig.cs:12 CONFIG_FOLDER_PATH = Path.Combine(Path.GetFullPath("."), "config"), :15 ...\config\oomtm450_soundspack_clientconfig.json; directory created at :40–:42, File.ReadAllText at :46, File.WriteAllText at :80. Absent categories (checked against evidence/api_surface.txt and all 27 sources). No registry access (the [Registry] category is absent). Findings #

  1. Client sends its own absolute local install path to the game host. SoundsPack.cs:34 puts Path.Combine(Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location), "sounds") into the ASKDATA payload. That string typically contains the local Windows account name; it is visible to the lobby host. In-game channel only, no third party, no credential value. Severity: low.
  2. Harmony postfix on PhysicsManager.Update (SoundsPack.cs:16). Standard framework bootstrap for this modding stack; the body is gated behind a "not yet registered" flag. Severity: informational.
  3. Writes one JSON config into <game>/config (ClientConfig.cs:80). Single LogInfo field. Severity: informational.
  4. 6,124 automated "magic signature" hits are false positives. Every hit is MZ/ZIP/7Z at a random offset inside one of the 601 compressed Ogg Vorbis files (e.g. sounds\100_gecs_dumbest_girl_alive_goalsong.ogg offset 15200 ZIP, sounds\2pac_hail_mary_goalsong.ogg offset 22770 ZIP, sounds\2000edmonton_goalhorn.ogg offset 13554 ZIP). No PE header parses at any reported offset, and hits_summary.txt records keyword hits: 0 with zero text-pattern hits. This is entropy-coded audio, not a hidden payload. Severity: informational (scan artefact).
  5. Content-licensing risk, not a code risk. The pack ships 601 commercially released songs/horns. That may attract a Workshop DMCA takedown (the mod would stop loading), but has no security consequence on the machine. Severity: informational.
  6. Game-version gate (SoundsPack.cs:103) only logs a warning for unsupported builds. Defensive. Severity: informational.

Evidence trail #

  • Method: SHA-256 inventory of 603 files (evidence/inventory.tsv — 604 rows including header, evidence/hashes_sha256.txt), PE header parsing (evidence/pe_info.txt), ilspycmd decompilation of the single managed DLL (27 C# files in sources/), full automated signature/keyword scan (evidence/scan_hits.tsv, hits_summary.txt), source review plus cross-check of api_surface.txt.
  • The 27-file source tree is byte-for-byte the same framework as 3578513105_Halloween_Music_Pack (identical 25-type set: Constants, FaceoffSpot, IceElement, LockDictionary, LockList, LockWeightedList, Logging, NetworkCommunication, PausableTimer, PlayerFunc, PuckFunc, ServerFunc, SoundsSystem, SystemFunc, TeamFunc, WeightErrorHandlingType, Zone, ZoneFunc, IConfig, ISubConfig, SoundsPack, PhysicsManager_Update_ClientPatch, ClientConfig, OldServerConfig, ServerConfig) — only the assets differ. Cross-checking the two mods against each other is a strong independent check that neither has been individually back-doored.
  • Keyword roll-up across every .cs: no match for http, HttpClient, WebClient, Socket, Registry, Process.Start, Assembly.Load, FromBase64String, GetAuthTicket, Clipboard, GetAsyncKeyState, DllImport, Marshal., Aes, Rijndael, CryptoStream, DownloadFile, DownloadString, Steamworks, powershell, schtasks, RunKey.
  • What could NOT be verified: the 601 .ogg files were hashed and signature-scanned but not decoded or listened to; no hidden executable was confirmed at any signature offset. Runtime playlist synchronisation on a live server was not executed. No REA binary note exists for this DLL.

Bottom line #

Keep. It is a 135 MB pile of audio plus the same small, readable, unobfuscated plugin used by this author's Halloween pack — it only talks to the game host over the game's own netcode channel, writes one JSON file in the game folder, and contains no network client, no registry access, no process execution, no crypto and no persistence. The only real caveat is legal (601 commercial tracks), not security.
