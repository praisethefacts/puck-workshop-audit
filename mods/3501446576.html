What it is #

A referee/rules-enforcement mod: offside, icing, high-stick and interference detection, penalties, referee votes, and on-ice referee signal graphics and whistle sounds. The managed DLL does all of the detection and rule state; the PNG/OGG/UI files are the visuals and audio it loads. It runs on a dedicated server (authority) with thin client-side patches for display, and it communicates with clients solely through the game's own Unity Netcode named-message API.

Findings #

  1. Very large Harmony patch surface (~55 patches) including collision, goal, penalty and server-spawn paths — Ruleset.cs and the *_Patch types in evidence/api_surface.txt. Justified by the mod's rules-enforcement purpose; all changes are game-rule state, not host-system access. Severity: informational.
  2. Netcode named messages used for referee state — NetworkCommunication.cs:40,65; traffic stays inside the game's own session transport, addressed to the connected players. Severity: informational.
  3. Local PNG loading via UnityWebRequestTexture on a file:// URI — RefSignals.cs:116-130. Looks like "web request" in string scans; it resolves to the mod's own images/refsignals folder. Not a download. Severity: informational.
  4. Automated scan noise explained — evidence/FACTS.md lists 36 binary hits ("MZ"/"7Z"/"ZIP" magic at offsets) inside images/refsignals/*.png, sounds/whistle.ogg and ui/penlabelui. These are compressed-payload magic bytes occurring inside legitimate media files; they are not embedded executables (entropy of the DLL is 6.0, no overlay, no second MZ/PE structure in the media files).
  5. No network/registry/process/crypto capability at all — 0 risky-API hits across 62 files; confirmed against evidence/api_surface.txt.
