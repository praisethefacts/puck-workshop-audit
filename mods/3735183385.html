1. Security re-check of the previous finding #

Old finding: AdminPanelCmd was executed for any client; admin test trusted a client-supplied SteamID.

Now:

  • OnNamedMessage(ulong senderClientId, ...) -> PlayerManager.GetPlayerByClientId(senderClientId) -> IsAdminPlayer(player). Non-admins are refused and logged: "[AdminPanel] Refused a command from non-admin client " + senderClientId.
  • IsAdminPlayer(player) is server-side: player.AdminLevel.Value > 0 or CheckAdminLocal(player.SteamId.Value.ToString()).
  • CheckAdminLocal = the server's admin_steam_ids.json (dedicated server only; created as [] in Environment.CurrentDirectory, hot-reloaded with a FileSystemWatcher), else the game's own AdminManager.IsSteamIdAdmin(steamId).
  • OnAdminCheckMessage ignores the payload, computes the answer from senderClientId, and replies "1"/"0" to that client only.
  • The client still sends its own SteamID in the AdminPanel_Check payload, but the server never reads it - no impersonation path. (Payload framing is validated: 0-2048 bytes, length checked.)
  • Local execution exists only for IsServer && IsHost (the operator running the server).
  • New VoteKickPatch blocks vote-kicks against server-admin SteamIDs and players with AdminLevel > 0.
  • Client-side RequireAdmin() gate is UI-only; server enforcement is what counts, and it is present.

Residual client-side wrinkle (informational): OnAdminCheckResult does not check the message sender, so a peer could make your panel believe you are admin. It grants nothing - the server still refuses every command from a non-admin - it only makes the UI attempt them.

3. Residual notes (not vulnerabilities) #

  1. admin_steam_ids.json semantics: if the file exists and is non-empty, only those IDs are admins and the game's own AdminManager admins are ignored; if empty/missing it falls back to AdminManager. Server operators must keep it valid JSON with real SteamID64s.
  2. FileSystemWatcher only listens for LastWrite; some editors save via replace/rename and may not hot-reload - restart the server or rewrite the file in place.
  3. ParseJsonStringArray is a naive quote scanner: any quoted token in the file becomes an "admin ID". A corrupted file could produce garbage entries (fail-closed in practice, but validate it).
  4. Client-side admin flag can be spoofed by a peer (AdminPanel_Result) - UI confusion only.
  5. Unsigned DLL + Steam auto-update: this verdict is tied to hash d14311cc...0b. If the Workshop "updated" date changes again, re-run scan.ps1 and this review.

5. Bottom line #

Fixed. Safe to use on a public server again, provided the server runs this build (B55) or newer and admin_steam_ids.json (if used) contains valid SteamIDs. The previous "any client can run admin commands" issue no longer exists: sender identity and admin status are both resolved server-side, and the old client-supplied SteamID is ignored.

Operational advice: on a dedicated server, put your admins in admin_steam_ids.json; if you rely on the game's own admin list instead, leave that file empty or delete it.
