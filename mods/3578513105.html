What it is #

A music replacement pack for Puck: it ships 50 Ogg Vorbis tracks and swaps them in for the game's faceoff and between-periods music (Halloween/horror themed — Ghostbusters, Thriller, X-Files, Monster Mash, and so on). The audio is inert data; the small SoundsPack_HalloweenMusicPack.dll is the standard oomtm450 "SoundsPack" framework plugin that registers the tracks and distributes the playlist over the game's own netcode channel so a server and its clients agree on which song plays.

The DLL is required for the pack to work — without it the .ogg files are never referenced.

Code analysis #

Bootstrap. oomtm450PuckMod_SoundsPack/SoundsPack.cs implements IPuckPlugin. OnEnable() builds a Harmony instance, logs a warning if Application.version is neither 1235 nor 897 (the two supported game builds, SoundsPack.cs:103), calls _harmony.PatchAll() (SoundsPack.cs:108), then reads either the server or the client config (SoundsPack.cs:115 / :120) and subscribes to Event_Everyone_OnClientConnected / Event_OnClientStopped. OnDisable() unregisters the message handler and calls _harmony.UnpatchSelf().

Harmony patches — exactly one. SoundsPack.cs:16 [HarmonyPatch(typeof(PhysicsManager), "Update")], inner class PhysicsManager_Update_ClientPatch, [HarmonyPostfix]: on a connected client it registers one named-message handler (SoundsPack.cs:28) and then, at most 12 times at 5-second intervals, asks the host for the playlist (SoundsPack.cs:34). No game logic is altered — this is a polling hook, not a gameplay modification.

Network — in-game netcode only, no internet transport. Every byte goes through Unity Netcode's CustomMessagingManager: NetworkCommunication.cs:52 SendNamedMessage(...), NetworkCommunication.cs:87 SendNamedMessageToAll(...), plus RegisterNamedMessageHandler on the plugin side. There is no HttpClient, WebClient, WebRequest, UnityWebRequest, Socket, TcpClient, UdpClient, named pipe or any other outbound transport anywhere in the 27 source files, and no URL or hostname appears in any source file. The traffic is player-to-host inside the already-established Steam/netcode session and is limited to the mod's playlist/metadata messages.

Filesystem — one config file, written inside the game folder. oomtm450PuckMod_SoundsPack.Configs/ClientConfig.cs:12 CONFIG_FOLDER_PATH = Path.Combine(Path.GetFullPath("."), "config"), :15 CONFIG_PATH = ...\config\oomtm450_soundspack_clientconfig.json; :36–:38 creates the folder, :43 File.ReadAllText, :80 File.WriteAllText. ServerConfig.cs does the same for oomtm450_soundspack_serverconfig.json. The only field in the client config is bool LogInfo. No deletions, no writes outside <game>/config, nothing written to the user's Documents/Desktop/AppData.

Absent categories (checked against evidence/api_surface.txt and all 27 source files). No registry access of any kind (the [Registry] grep category is empty for this mod). No process creation, no Process.Start, no shell. No Assembly.Load / Assembly.LoadFrom / dynamic code loading. No crypto APIs (Aes, Rijndael, CryptoStream, RNGCryptoServiceProvider) — the [Crypto] category is absent. No base64/FromBase64String. No P/Invoke, no DllImport, no Marshal. No input capture (GetAsyncKeyState, Keyboard.current, clipboard), no screen capture, no credential/token/session access (GetAuthTicket never appears), no Steamworks API use. No persistence (no Run key, no scheduled task, no service, no startup shortcut). No AV/AMSI/ETW evasion. No packing or obfuscation. No anti-debug or environment fingerprinting beyond the Application.version equality check.

Findings #

  1. Client sends its own absolute local install path to the game host. sounds/SoundsPack.cs:34 includes Path.Combine(Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location), "sounds") in the ASKDATA payload. On a typical Steam install that string contains the local Windows account name (...\Users\<name>\...) and is visible to whoever hosts the lobby. Not exfiltration (in-game channel only, no third party), no credential value, but it is unnecessary path disclosure. Severity: low.
  2. Harmony patch of PhysicsManager.Update (sounds/SoundsPack.cs:16). A per-frame postfix is the standard plugin bootstrap used by this modding framework; it only runs its body when the client is connected and not yet registered, then sets a flag. No gameplay state is modified. Severity: informational.
  3. Writes one JSON config into the game directory (...Configs/ClientConfig.cs:80). Contained to <game>/config, single field LogInfo, no user data collected. Severity: informational.
  4. 673 "magic signature" hits (MZ/ZIP/7Z at random offsets) reported by the automated scan are false positives. Every hit lands inside a compressed Ogg Vorbis file (sounds\betweenperiodsmusic_*.ogg, etc.), where those byte sequences occur by chance in the entropy-coded audio stream. evidence/FACTS.md already flags none of them as notable; hits_summary.txt records keyword hits: 0 and zero text-pattern hits across the whole package. Severity: informational (scan artefact).
  5. Game-version gate (sounds/SoundsPack.cs:103) refuses to run on builds other than 1235/897. Defensive, not evasive — it only logs a warning. Severity: informational.

Evidence trail #

  • Method: SHA-256 inventory of all 52 files (evidence/inventory.tsv, evidence/hashes_sha256.txt), PE header parsing (evidence/pe_info.txt), ilspycmd decompilation of the single managed DLL into 27 C# files (sources/), automated magic-signature/keyword scan (evidence/scan_hits.tsv, hits_summary.txt), free-text pattern review of the decompiled sources and api_surface.txt.
  • Reviewed in full: SoundsPack.cs, NetworkCommunication.cs, ClientConfig.cs, ServerConfig.cs, Constants.cs, plus the shared Codebase helpers (SoundsSystem.cs, SystemFunc.cs, ZoneFunc.cs, PlayerFunc.cs, LockWeightedList.cs, …). Cross-checked the keyword roll-up across every .cs file: no match for http, HttpClient, WebClient, Socket, Registry, Process.Start, Assembly.Load, FromBase64String, GetAuthTicket, Clipboard, GetAsyncKeyState, DllImport, Marshal., Aes, Rijndael, CryptoStream, DownloadFile, DownloadString, Steamworks, powershell, schtasks, RunKey.
  • What could NOT be verified: the 50 .ogg files were not individually decoded/played (only hashed and scanned for embedded executables — the 673 hits are inside the audio stream, and no PE header parse succeeds at any of those offsets, so there is no hidden executable payload). The runtime behaviour of the server-side half of the playlist sync was not executed; it was read statically only. No REA binary note exists for this mod's DLL.

Bottom line #

Keep. It is a music pack plus a small, readable, unsigned-but-unobfuscated plugin that only talks to the game host over the game's own netcode channel, writes one JSON file inside the game folder, and contains no network client, no registry access, no process execution, no crypto and no persistence. The only nit is that it tells the lobby host the local path of your install folder — harmless, and the same code shipped by this author's other sound packs.
