The short version

Every file hashed, every managed DLL decompiled, every capability read. One machine, one snapshot, no sandbox detonation.

Back to the ledger

Audit date: 2026-10-26. Target: every mod installed under [local path] (Puck, app 2994020).

You asked for the kinds of things that actually hurt people — token/credential grabbers, ransomware, miners, plus stealers, RATs, persistence and the usual Steam-account theft patterns. That is what the checks below were built to find. No malicious code was found in any of the 63 mods; the notable results are privacy/telemetry findings and two mods whose Workshop listing no longer exists.

What was checked, per mod #

  1. Full file inventory + SHA-256 of every file (evidence/inventory.tsv, evidence/hashes_sha256.txt), so the report is tied to exact bytes.
  2. Workshop metadata from Steam's public API (title, author SteamID64, size, subscribers, published date) — matched against on-disk size to confirm the installed copy is the real one.
  3. PE parsing of every executable (evidence/pe_info.txt): managed vs native, x86/x64, .NET version, sections, overlay/appended data, entropy, signature.
  4. Decompilation of every managed DLL to readable C# with ilspycmd into sources/, then read: plugin bootstrap, Harmony patches, every network call, every file/registry/process API, crypto/encoding, reflection, obfuscation.
  5. Pattern + string scan of every binary and text file (evidence/scan_hits.tsv, evidence/text_hits.txt) for: URLs/IPs/stratum/xmrig/Monero, browser credential paths (Login Data, WebData, Cookies), wallet files (Exodus/MetaMask/wallet.dat), GetAsyncKeyState/SetWindowsHookEx/OpenClipboard/BitBlt (keylog, clipboard, screen), VirtualAlloc/CreateRemoteThread/WriteProcessMemory (injection), Assembly.Load/ FromBase64String (packed/reflective loaders), AMSI/ETW patching, %APPDATA% staging, CurrentVersion\Run/scheduled tasks (persistence), AES/Rijndael decrypt loops (ransomware), and shell/powershell/certutil/bitsadmin/vssadmin command strings.
  6. API-surface summary per mod (evidence/api_surface.txt) — a fast cross-check that the decompiled code and the binary agree.
  7. REA (open_binary → inspect_managed_artifact → inspect_managed_members → inspect_managed_native_boundaries → close_binary) on every DLL for an independent second opinion on identity, imports/exports, P/Invoke and user strings; notes in _harness/rea/.
  8. Asset/embedded-payload checks: bundles/PNGs/OGG/PSD checked for appended executables, archives or scripts (offset-based, not just "does MZ appear somewhere").
  9. Obfuscation handling: where a DLL was obfuscated, its string table was decoded offline rather than giving up (see 3776968217_RHL_COMPANION).

Limitations — please read #

  • Nothing was executed. This is a static audit. A mod could be malicious only in ways that require a live game/server (for example a server sending instructions no client code obviously implies). Server-side behaviour of every backend (puckstats.io, poncepuck.net, tlanpuck.com, rhladminpanel…, 155.212.135.111) was not tested.
  • No native disassembler on this machine. Ghidra/Hopper/IDA/Kuna were not configured, so native code (only 3800009738/native/x64/WebView.dll here) and heavily obfuscated methods were reviewed via exports, strings and API surface rather than full instruction-level decompilation. That file is a known open-source WebView plugin, so confidence is still high.
  • Short-magic false positives. The scanner's short signatures (MZ, ZIP, 7Z) also match random byte pairs inside compressed assets (PNG/OGG/Unity bundles), which is why scan_hits.tsv shows many hits there. Only hits at file starts (or with a plausible appended-blob structure) were treated as real; the "appended payload" checks were done separately and found nothing.
  • Two mods are unlisted. 3775350613 and 3778714545 no longer exist in Steam's Workshop API (result: 9), so their author, subscriber count and size cannot be confirmed. Their code was reviewed normally and is clean, but the provenance is unverifiable — flagged in each report.
  • One mod was unsubscribed during the audit. 3827631915 (Shared Practice) was removed by Steam at ~20:56 while this run was ongoing, so it is not part of the 61 on-disk folders. Its earlier audit (CLEAN) is at [local path].
  • Signing: every Puck mod here is unsigned (there is no signing convention in the game), so "unsigned" is not itself a red flag in this collection and is only mentioned for completeness.

Re-audits after a Workshop update #

A Workshop updated timestamp newer than a report means the DLL changed and the old verdict no longer applies to the bytes on disk. Re-audit procedure used here:

  1. hash the new file and compare with evidence/hashes_sha256.txt;
  2. copy the old audit to _harness/_old_<modid>/ (sources, evidence, report) for diffing;
  3. delete the mod's audit folder so stale decompiled files cannot linger;
  4. re-run _harness/scan.ps1 -OnlyId <modid> -Force (fresh evidence + full decompile);
  5. diff the source trees, then re-verify the previously reported finding in the new code;
  6. rewrite REPORT.md, update the verdict table above, and log the change in the re-audit table.
